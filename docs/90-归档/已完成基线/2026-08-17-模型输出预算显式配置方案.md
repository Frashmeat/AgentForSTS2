# 模型输出预算显式配置方案

> 文档定位：定义 Recipe 输出预算与模型/代理实际能力之间的显式配置边界。
>
> 关联任务：`.trellis/tasks/08-05-sts2-character-cross-item-composition` O9。
>
> 最后更新：2026-08-17

## 1. 背景与证据

当前 `mod.generate.single` Recipe 为完整多文件 bundle 声明 `16,384` tokens。该值表达 Feature
允许的业务上限，不代表每个模型或 OpenAI-compatible 代理都接受同样的请求预算。

O9 fresh installed closure 在同一 endpoint、model、credential 和请求格式下完成受控复现：

```text
model: deepseek-v4-pro
max_tokens=4096  -> HTTP 200
max_tokens=8192  -> HTTP 403
max_tokens=16384 -> HTTP 403
```

因此当前失败不是 Key 失效，而是代理拒绝超过其允许范围的请求参数。现有 Adapter 又把 `401`
与 `403` 都映射为 `model.authentication`，使持久化错误给出了错误的恢复方向。

## 2. 目标与非目标

目标：

- 让用户显式声明当前模型/代理可接受的最大输出预算；
- 保留 Recipe 对业务任务所需上限的所有权；
- 让 snapshot、hash、HTTP body 和持久化证据描述同一次真实请求；
- 区分无效凭据与请求被拒绝；
- 保持现有严格 typed output、FIFO、bounded retry 和 feedback 语义不变。

非目标：

- 不自动探测 Provider 能力；
- 不根据错误自动换模型、endpoint、response format 或预算；
- 不把完整 Item 自动拆成文件级 DAG；
- 不放宽 JSON/schema 校验，不从截断内容猜测结果；
- 不新增 Feature 级 transport retry 或无限重试。

## 3. 设计决策

新增一个用户级可选配置：

```json
{
  "llm": {
    "max_output_tokens": 4096
  }
}
```

有效输出预算只按一个公式解析：

```text
effectiveMaxOutputTokens =
  min(recipe.maxOutputTokens, configured llm.max_output_tokens)
```

未配置时不施加额外 Provider 上限，保持 Recipe 当前值。配置值必须落在 Runtime 已允许的
`1..=65,536` 范围内；无效值属于 `model.configuration`，在创建模型请求和 HTTP 调用前失败。

示例：

```text
Recipe upper bound:     16384
Configured upper bound:  4096
Effective request:       4096
```

配置是用户对当前 endpoint/model 能力的明确声明，不是系统推测出的“兼容补丁”。模型或 endpoint
变化后，用户可以在 System 高级设置中调整该值。

## 4. 请求预算解析流程

```text
Pinned Recipe
  -> recipe.maxOutputTokens
              \
               -> min -> effectiveMaxOutputTokens
              /
Validated Settings
  -> llm.max_output_tokens

effectiveMaxOutputTokens
  -> ModelRequestSnapshot v1
  -> snapshot SHA-256 / Run provenance
  -> Runtime ModelRequest
  -> provider-native max_tokens
```

预算解析属于 Feature 请求装配边界。Adapter 只能忠实传输已经固定的
`ModelRequest.max_output_tokens`，不能在发送时再次截断或改写。

## 5. Snapshot、Hash 与恢复语义

有效预算必须在创建 `ModelRequestSnapshot` 前解析，并进入 snapshot 的
`request.maxOutputTokens`。模型请求 hash 因此绑定有效值，而不是 Recipe 原始值。

ExecutionGraph checkpoint 和 Run 仍保存现有的安全、散列化 provenance，不保存 credential、完整
Prompt、Provider body 或 raw completion。Resume 恢复已成功 checkpoint；未完成节点按当前
Graph 已固定的请求身份继续，不允许静默改预算后把它解释为同一次请求。

设置变更只影响之后新建的 Direct Run 和 Graph。staged Plan/Generate 在 Graph 创建时将 validated
limits 固定进 blueprint；Resume 始终使用该 pinned limits，即使当前 Settings 已改变，也不会就地
改写历史 snapshot/hash。要采用新设置必须创建新 Graph。

## 6. 错误分类

| 条件 | Adapter 类型 | 持久化 family | 用户动作 |
| --- | --- | --- | --- |
| HTTP 401 | `ModelError::Authentication` | `model.authentication` | 检查 API Key |
| HTTP 403 | `ModelError::Rejected` | `model.request_rejected` | 检查预算、模型和代理策略 |
| HTTP 429 | `ModelError::RateLimited` | `model.rate_limited` | 按现有有界退避重试 |
| HTTP 5xx / transport | `ModelError::Transport` | `model.transport_failed` | 按现有有界策略处理 |
| 有效预算范围无效 | `ModelError::Configuration` | `model.configuration` | 修正 System 配置 |
| 输出在有效预算处截断 | Feature typed failure | `model.output_truncated` | 提高上限或更换模型 |

只有未来获得可信且结构化的 invalid-key 证据时，特定 403 才可以被重新分类为鉴权失败；不能根据
状态码、自由文本或 Provider 名称猜测。

## 7. System UI

System 页的 LLM 高级设置增加“最大输出预算”数值输入。普通 Plan、Single、Composition 和
Character 生成流程不暴露 Token、Graph、retry 或 Provider 技术控制面。

UI 只负责：

- 展示和保存配置值；
- 在本地阻止空值之外的非整数或越界值；
- 将后端 authoritative validation 的配置错误显示为可操作状态。

UI 不负责估算某个任务需要多少 tokens，也不根据某次失败自动修改设置。

## 8. 影响范围

实现阶段需要同步以下边界：

- `ats-adapters::LlmConfig`、默认/反序列化/环境覆盖和配置验证；
- Feature Recipe 到 `ModelRequestSnapshot` 的请求装配；
- Runtime request/snapshot hash 一致性；
- OpenAI-compatible HTTP 状态码映射；
- Tauri Settings snapshot/patch DTO；
- System 页高级设置、frontend guards 和表单测试；
- Adapter、Feature、desktop 与 frontend 的针对性测试。

不改变 Pack、Truth、ItemDefinition、Resource、Artifact 或公开 Feature catalog。

## 9. 实施顺序

1. 扩展配置 schema、默认值、校验和 Settings DTO。
2. 在 snapshot 创建前解析有效预算，并让 hash 与 Runtime request 使用同一值。
3. 分离 401/403 typed mapping。
4. 在 System 高级设置加入单一数值控件。
5. 完成针对性测试、跨层检查和全量机器门禁。
6. 代码提交后构建 replacement candidate，创建新的物理验收根重新执行 O9。

## 10. 验证计划

必须证明：

- Recipe `16384` + 配置 `4096` 得到 snapshot/request/body 一致的 `4096`；
- Recipe 小于配置时保持 Recipe 值；未配置时保持 Recipe 值；
- `0`、负值、非整数和大于 `65,536` 的值在 HTTP 前失败；
- snapshot/hash 会随有效预算变化，旧 checkpoint 不被静默重解释；
- OpenAI-compatible body 精确发送有效 `max_tokens`；
- 401 为 `model.authentication`，403 为 `model.request_rejected`；
- 4096 下若内容放不下，仍严格返回 `model.output_truncated`；
- System 表单读写、校验和凭据脱敏保持正确；
- FIFO、SSE、retry、strict schema 和 semantic feedback 回归不变。

## 11. Wrong vs Correct

错误：Adapter 在 snapshot 已记录 `16384` 后，发送前静默改成 `4096`。

```text
snapshot/hash: 16384
HTTP body:      4096
```

这会破坏重放审计、Run provenance 和 Resume 身份。

正确：Feature 请求装配在创建 snapshot 前解析有效预算。

```text
Recipe 16384 + Settings 4096
  -> effective 4096
  -> snapshot/hash 4096
  -> Runtime request 4096
  -> HTTP body 4096
```
