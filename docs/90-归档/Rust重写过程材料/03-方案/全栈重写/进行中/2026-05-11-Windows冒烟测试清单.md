## 0. 一次性准备（约 10 分钟）

1. **拷贝配置模板**
   ```powershell
   Copy-Item runtime\agentthespire.config.example.json runtime\agentthespire.config.json
   ```
2. **编辑 `runtime\agentthespire.config.json`**：
   - `llm.provider`：用 e-flowcode.cc 等 Anthropic 兼容代理填 `"anthropic"`；用 new-api / one-api 填 `"openai"`
   - `llm.api_key` / `llm.base_url` / `llm.model`：按代理给的填
   - `image_gen.*`：若代理支持图片，填一份；不支持则留空（asset_generate handler 跑到图片段会失败，这是预期）
3. **启动桌面端**：`.\dev.ps1`
4. **打开 / 新建一个工程**：进 Dashboard → Project 卡片 → 选父目录 + 项目名，确认 `<父目录>/<项目名>/{project.json, items/, artifacts/, history/, .ats/}` 创建出来。

> **任何时候出问题**：
> 1. 不要关 Tauri 窗口（保留 console / devtools 日志）
> 2. 在仓库根跑 `pwsh -ExecutionPolicy Bypass -File scripts\collect-bug-report.ps1 -ProjectRoot <你工程路径>`（PS 5.1 也可，`powershell` 替代 `pwsh`）
> 3. 把生成的 `bug-report-*.zip` 附到新 issue
> 4. issue 标题：`[smoke] <handler 或 page 名> - <一句话症状>`

## 1. 9 handler 逐项

### 1.1 text_generate（LLM 流式文本）
- **触发**：Dashboard → Llm 卡片 → 输入任意 prompt（如 "请用中文写 3 句 sts2 卡片设计建议"）→ 提交。
- **预期**：流式 token 逐步出现；完成后 Job 进 Completed；`<project>\history\<ts>--<jobId>.json` 写入，`status="completed"`，`result.content` 含 LLM 输出。
- **关键看点**：`stage` 进度从 `running` → 中间 `stream-tick` → `completed`；流式延迟可以观察是否分块。
- **常见 bug**：中文乱码（UTF-8 边界）、网络超时无重试、`base_url` 末尾斜杠处理错误。

### 1.2 code_generate（C# 卡片代码）
- **触发**：ModEditor 页 → 任选一个 PlanItem → 触发 code_generate。
- **预期**：`<project>\artifacts\<itemId>\<ClassName>.cs` 写入；Job 完成；`items\<itemId>.status.json` 状态 → `generated`；audit log 多一条 `job.completed`。
- **关键看点**：生成的 .cs 文件 fence 解析正确（不带 ```csharp ... ```）；编码 UTF-8 无 BOM。
- **常见 bug**：fence 残留、类名提取错（用了 prompt 里的字面值而非 LLM 返回）、artifacts 目录权限失败。

### 1.3 asset_generate（C# + PNG 一起出）
- **触发**：ModEditor 选一个需要图片的 item → asset_generate。
- **预期**：`<itemId>\<ClassName>.cs` + `<itemId>\<ClassName>.png` 同时出；image_proc 启发式背景去除应用过（PNG 有 alpha 通道）；status → `generated` 且 `cs_path` / `png_path` 都填。
- **关键看点**：若 `image_gen` 没配，应该在 stage 报清晰错误而非闷崩。
- **常见 bug**：image base_url 与 LLM base_url 串用错、PNG 写入路径含中文崩、rembg 启发式算法处理深色背景效果差（已知，不算 bug）。

### 1.4 batch_custom_code（多 item 批量）
- **触发**：BatchGeneration 页 → 勾选 ≥3 个 item → 提交。
- **预期**：单个 Job 串行调度多 item；每个 item 写 .cs；任一 item 失败不阻塞其它（fail_fast=false 默认）；最终 Job 是 `completed` 还是 `failed` 取决于是否所有 item 都成功。
- **关键看点**：进度 `percent` 是否随 item 推进；`result` 含每 item 子结果数组。
- **常见 bug**：并发竞争 items/ 目录、长时间任务无心跳。

### 1.5 build_project（dotnet publish）
- **触发**：ModEditor → Build 按钮（需要本机装了 dotnet SDK 6+）。
- **预期**：调 `dotnet publish` 子进程；stdout/stderr 流入 history 日志；启发式判定成功（含 `Build succeeded`）→ Job completed。
- **关键看点**：`project_utils` 是否处理中文路径；build log 应能被后续 log_analysis 读取。
- **常见 bug**：dotnet 不在 PATH 时报错不清晰、长路径（>260 字符）失败、stderr 编码（GBK vs UTF-8）。

### 1.6 package_project（zip 打包）
- **触发**：ModEditor → Package 按钮。
- **预期**：用 zip crate 把 `<project>\artifacts\` 打成 release tarball，落到 `<project>\history\<jobId>.zip` 或类似位置。
- **关键看点**：含中文文件名是否能正确进 zip（zip crate UTF-8 flag）；大文件耗时进度更新。
- **常见 bug**：空 artifacts 目录处理、符号链接 / `.tmp` 残留文件混进 zip。

### 1.7 single_asset_plan（单 item 计划）
- **触发**：Dashboard → SingleAssetWorkflow 卡片 → 输入需求文本 → 提交 plan。
- **预期**：LLM 出 JSON → 解析成 1 个 PlanItem → 写 `plan.json` / `items\<id>.json`；后续可立刻接 asset_generate。
- **关键看点**：JSON fence / 散文混合输出的容错（应能从 markdown 代码块里抽 JSON）。
- **常见 bug**：LLM 输出尾部多 trailing comma 致解析失败、字段名大小写不一致（snake vs camel）。

### 1.8 log_analysis（构建日志诊断）
- **触发**：LogAnalysis 页 → 粘贴 build log 或选 log_path → 提交。
- **预期**：LLM 出 markdown 诊断；写到 history；Job result.content 含 markdown。
- **关键看点**：超大 log（>50KB）截断策略；非 UTF-8 编码（dotnet 中文 Windows 默认 GBK）能解码。
- **常见 bug**：log 太大 token 超限错误不清晰、log_path 文件不存在静默崩。

### 1.9 knowledge_refresh（反编译知识库刷新）
- **触发**：Dashboard → Knowledge 卡片 → Refresh 按钮（前置：本机装了 `ilspycmd` + 配了 `sts2_path`）。
- **预期**：检查 manifest 缓存命中 → 不命中则跑 ilspycmd → 写 `%APPDATA%\AgentTheSpire\knowledge\game\*.cs`；BaseLib 从 GitHub Releases 拉 → `baselib\BaseLib.decompiled.cs`；manifest 更新；Job completed。
- **关键看点**：ilspycmd 不在 PATH 报错清晰（提示 `dotnet tool install -g ilspycmd`）；缓存命中早退（无网络也能跑通第 2 次）。
- **常见 bug**：GitHub API 限速、网络代理需求、sts2.dll 路径含中文。

## 2. 4 page 逐项

### 2.1 DashboardPage（首页）
- **看 8 个 Card**：Health / Capabilities / Project / SingleAssetWorkflow / Jobs / Knowledge / Planning / Codegen / Llm（实际 9 个）。
- **预期**：HealthCard 显示 `db_ready=false`（桌面端无 DB）+ `llm_ready` 按配置；CapabilitiesCard 列 OS / dotnet / ilspycmd 检测结果；JobsCard 列最近 N job 含 9 种 kind。
- **常见 bug**：Card 之间互相依赖时初始加载顺序错（如 ProjectCard 没加载好就跳到 SingleAssetWorkflow 报 `no active project`）。

### 2.2 ModEditorPage
- **预期**：左侧项目结构树（artifacts / items）+ 右侧 PlanItem 详情 + plan_artifact 状态色（pending/in_progress/generated/reviewed/failed）。
- **常见 bug**：plan.json 不存在时白屏、items/ 含 .tmp 文件误显示。

### 2.3 BatchGenerationPage
- **预期**：列出当前 plan 所有 item + 多选 checkbox + 提交按钮；提交后进度条逐 item 推进。
- **常见 bug**：选中状态在提交后丢失、进度条卡在 99%。

### 2.4 LogAnalysisPage
- **预期**：文件选择器（选 build log）或粘贴框；提交后 markdown 渲染诊断。
- **常见 bug**：markdown 渲染缺组件（如表格 / 代码块未高亮）、长 log 上传超时。

## 3. 边界用例（每 handler 都顺手试一下）

| 场景 | 预期行为 |
| --- | --- |
| 中途按 Cancel | LLM 流式任务 5 秒内真断网（reqwest stream drop）；Job 进 Cancelled；audit log 一条 cancel |
| `api_key` 故意填错 | 401 错误清晰回到 UI；Job 进 Failed 而非 Pending 卡死 |
| `base_url` 末尾带 / 与不带 | 都应该工作（客户端内部规整） |
| 工程路径含中文（如 `D:\我的项目\卡片1`） | 所有 .cs / .png / .json 写入正常 |
| 工程路径 > 260 字符 | 走 `\\?\` 长路径模式不崩 |
| 同一工程开两个 Tauri 实例 | 第二个应该报 `Locked` 错而非互相覆盖文件 |
| `runtime\agentthespire.config.json` 不存在 | 启动应给出明确提示而非崩 |

## 4. 报 bug 流程

1. 复现完一遍症状（最好能稳定复现，不行也没关系，先记下来）
2. **不要关 Tauri 窗口**——devtools console 是关键线索
3. 跑收集脚本：
   ```powershell
   .\scripts\collect-bug-report.ps1 -ProjectRoot <工程根> -OutDir .\bug-reports
   ```
   生成 `bug-reports\bug-report-YYYYMMDD-HHMMSS.zip`
4. 提 GitHub issue（仓库 issue 模板会自动填空）：
   - 标题：`[smoke] <handler/page> - <症状>`
   - 模板字段：handler/page、复现步骤、预期 vs 实际、provider/model（**不要贴 api_key**）、附 zip
5. 如果 console 里有 `RUST_BACKTRACE` 之类的 panic，把整段贴 issue body（zip 里也会有，但 inline 更快看）

## 5. 我（Claude）这边怎么消化

收到 issue 后我会按下面顺序看：
1. 读 `audit.log` 时间线倒推到失败点
2. 看 `history\<failed-jobId>.json` 的 `error` + `progress.stage`
3. 看 `recent_history\` 中前后 job 是否影响
4. 看 `config-redacted.json` 验证配置是否正常
5. 看 `sysinfo.txt`（dotnet / ilspycmd 版本、OS build）
6. 重现 → 改 → 提 fix commit → 关 issue

## 6. 收集脚本能抓什么 / 不抓什么

**抓**（脱敏后）：
- `runtime\agentthespire.config.json`（api_key → `[REDACTED]`）
- `%APPDATA%\AgentTheSpire\config.json` / `recent_projects.json` / `logs\*`（同样脱敏）
- 工程的 `.ats\audit.log` + `.ats\version` + `history\*.json`（最近 50 条）+ `items\*.status.json`
- `sysinfo.txt`：OS / dotnet --info / ilspycmd --version / git rev-parse HEAD / cargo --version
- `.ats\lock` 内容（PID，用于排查锁卡住）

**不抓**：
- `credentials.json`（永远不动）
- `artifacts/`（用户代码 + 图片，体积大 + 可能涉及版权）
- 任何 `api_key` / `session_secret` / `credential_secret` 原文

> 如果 bug 必须看 artifacts 才能修，issue 里我会请用户单独 zip 相关那一个 item 的产物。
