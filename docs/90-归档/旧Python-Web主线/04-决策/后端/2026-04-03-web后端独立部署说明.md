## 当前状态

本文最初用于说明 `web-backend` 可独立启动、独立维护、独立发布的阶段性口径。该阶段目标已经完成，但部署主线已经在 2026-05-04 进一步收口。

当前不再推荐单独维护一套 `web` 独立部署脚手架，也不再推荐 `hybrid`、根目录双 compose、`.env.web/.env.workstation` 或 `tools/docker/*` 作为当前部署入口。

## 当前部署主线

唯一推荐部署拓扑：

| 组件 | 运行位置 | 职责 |
| --- | --- | --- |
| `frontend` | 本机进程 | 静态前端入口 |
| `local-workstation` | 本机进程 | 本机 STS2、Godot、Mods、CLI、本地工作流 |
| `web` | Docker | 平台 API、用户、任务、配额、管理端 |
| `web-workstation` | Docker 内网 | Web 服务器执行面，只接受 `web` 调度 |
| `postgres` | Docker | 平台数据库 |

唯一人工配置真实源：

```text
runtime/agentthespire.config.json
```

唯一部署入口：

```powershell
powershell -File .\tools\tools.ps1 package app
powershell -File .\tools\tools.ps1 deploy app
powershell -File .\tools\tools.ps1 deploy app -DryRun
powershell -File .\tools\tools.ps1 stop app
```

## 当前边界

- `web` 仍是独立后端角色，入口为 `backend/main_web.py`，注册 Web 路由集合。
- `web-workstation` 运行工作站后端角色，入口为 `backend/main_workstation.py`，只作为 Docker 内网执行面。
- `web` 通过 `http://web-workstation:7860` 调度 `web-workstation`。
- 前端只连接本机 `local-workstation` 与 `web`，不直接连接 `web-workstation`。
- 部署脚本从 `runtime/agentthespire.config.json` 生成 `runtime/generated/web.config.json`、`runtime/generated/web-workstation.config.json`、`runtime/generated/local-workstation.config.json`、`runtime/generated/runtime-config.js` 与 `runtime/generated/docker.env`。

## 历史说明

旧阶段的“Web 后端独立部署”强调：

- `backend/main_web.py` 与 `backend/main_workstation.py` 职责分离。
- 同一个前端壳可以同时访问工作站接口与平台接口。
- `full` 运行角色退出当前实现基线。

这些结论仍然有效；失效的是旧部署脚手架和旧配置口径。

当前实现不再维护：

```text
tools/docker/*
docker-compose.web.yml
docker-compose.workstation.yml
.env.web.example
.env.workstation.example
tools/latest/package-release.ps1
tools/latest/deploy-docker.ps1
tools/latest/stop-deploy.ps1
tools/latest/build-workstation-installer.ps1
```
