## 1. 当前结论

Game Pipeline Provider foundation、显式模型输出预算和安装态 Character Composition E2E 已经给出足够证据，说明不能继续通过调整 Prompt、重试次数或固定 Graph 上限维持“模型直接作者化原生文件”的边界。

当前 `deepseek-v4-pro` 生成的 17 个 Item 原生文件全部进入编译修复。本地 Repair Campaign 成功修复 11 个后，因 Graph 累计 20 次 semantic request 达到既有硬上限而暂停。这不是一个需要单独增大预算的局部故障，而是 AI 仍然拥有原生文件作者权所导致的边界缺陷。


## 2. 核心边界

### AI

AI 只生成受 Capability Catalog 和 Schema 限制的 Behavior IR。AI 不再生成 source、namespace、class name、localization table、Resource path、project file 或 package manifest。

### Game Pack / Truth

Pack 声明 Item 类型、Capability Catalog、文件角色、Adapter 身份和 Pipeline profile。Truth 仍是当前游戏/API/工具链事实的唯一来源。Pack 不携带任意 shell 或 native plugin。

### Game Adapter

Game Adapter 是随应用发布的受信代码，将 pinned Behavior IR 确定性渲染为对应游戏的 source/data files。合法 IR 若产生不可编译代码，属于 Adapter 缺陷，不得再交给 AI 猜测 API。

### Core / Feature / Runtime

Core 只保留跨游戏稳定合同：DAG、FIFO queue、Run/Graph/Artifact、checkpoint、typed failure、cancellation、transaction 和 atomic publish。不同游戏仍由各自 Pipeline Provider 定义 Validate/Build/Package。

## 3. 确定性数据流

```text
confirmed localization  -> Localization Renderer
ResourceBinding         -> Asset Publisher
ReferenceBinding        -> Identity / Pool Resolver
Behavior IR             -> Game Behavior Adapter
Pack Pipeline           -> Validate / Build / Package
```

真实游戏人工验收后的单 Item 语义反馈只作用于目标 Behavior IR，并绑定 source Graph revision、`itemId`、definition hash 和 Behavior hash。原文只在本次 worker 请求内存在；调整后本地重渲染并复验整个闭包，不重写其他 Item 或已确认数据。设计意图变化必须回到 Item/Draft 编辑。

## 4. 可靠性策略

- HTTP timeout/429/5xx 仍在共享 FIFO 中有界退避。
- Behavior JSON/schema 错误只反馈当前 semantic node。
- capability/argument/reference 错误只修订当前 Item IR。
- Adapter、编译、工具链、存储和发布错误是 local failure，不消耗 AI 修订。
- 每个已规划 semantic node 拥有一次基础执行权；共享预算只限制额外反馈。
- `semanticRequestCount` 保留为审计值，不再剥夺其他节点的首次执行机会。
- 重复诊断+重复 candidate、无变化 replacement 和节点轮次耗尽仍安全停止。

## 7. 完成标准

父任务只在以下事实成立后完成：

1. 生产链路不再让 AI 作者化原生游戏文件。
2. STS2 五类结构化 Item 的确定性 Adapter 通过真实编译。
3. 多游戏仍通过各自 Adapter/Pipeline 扩展，Core 不增加游戏分支。
4. Graph 恢复、反馈、事务和 Artifact 不变量通过全量机器门禁。
5. 新 candidate installed closure 和真实 STS2 人工门禁完成。

## 9. 人工语义验收与反馈

当前真实 STS2 验收已证明，Typed Behavior IR 通过结构、渲染和编译门禁仍不能自动证明真实玩法符合已确认预期。下一实施任务是将人工验收反馈收口为单 Item 诊断，以 hash/ref 持久化，从 succeeded source 派生新 Graph/Run/Artifact，并且不保存反馈原文或完整 Prompt。

详细合同、迁移和验收要求见 [`人工真实验收与单 Item 语义反馈闭环方案`](./人工真实验收与单Item语义反馈闭环方案.md)。方案当前只完成设计，不授权构建 replacement candidate。
