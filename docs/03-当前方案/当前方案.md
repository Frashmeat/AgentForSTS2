## 3. 稳定架构约束

### 3.1 Core 与双壳

- `ats-core` 承载领域逻辑，不依赖 `axum` 或 `tauri`。
- `src-tauri` 是桌面壳，通过 Tauri IPC 调用 core，不启动本地 HTTP 服务。
- `ats-web` 是轻量 HTTP 壳，当前只装配 health、knowledge、planning、codegen、LLM 和静态资源。
- `ats-cli` 提供构建、部署、日志、停止和模板命令，不复制 core 业务逻辑。

### 3.2 共享前端

- React/TypeScript 前端由桌面和 Web 共用。
- `src/services/tauriApi.ts` 是 API 签名权威，`webApi.ts` 必须在编译期满足同一导出形状。
- `src/services/api.ts` 只负责根据 `__IS_TAURI__` 选择实现，页面不直接分叉业务逻辑。
- 路由使用 `HashRouter`，同时适配 Tauri webview 和静态 Web 部署。

### 3.3 工程与任务数据

- 桌面端项目采用自包含工程文件夹，不依赖数据库。
- `.ats/`、`items/`、`artifacts/`、`history/`、`Generated/` 和项目元数据共同形成可追溯记录。
- 文件更新优先使用临时文件加原子替换；生成或 compile gate 失败时不得留下半成品正式资源。
- 同一工程使用操作系统文件锁防止多进程并发写入，常驻诊断文件不等同于持锁状态。

### 3.4 启动与失败边界

- Tauri 启动期的 ML、缓存或索引预热必须后台执行，并通过状态接口暴露进度；不得阻塞窗口显示。
- Web 端先完成配置和路由装配，再绑定端口，并通过 Ctrl+C/SIGTERM 优雅停机。
- 非致命外部能力失败应降级并给出可行动提示；配置、鉴权、网络、工具链和写盘错误必须可区分。

### 3.5 通用流水线与 Game Pack

长期边界采用“一条通用 Mod 生产流水线 + 多个 Game Pack”：

- 引擎负责资源获取、索引、生成、验证、构建、打包、事务和任务追踪的通用机制。
- Game Pack 声明游戏真相源、工程骨架、资源规格、稳定验证规则、构建步骤和交付布局。
- 游戏本地化富文本标签由 Game Pack 资源规格显式列举，通用生成器只负责装配和确定性校验，不在 handler 中硬编码 STS2 标签。
- 不为每个游戏复制一套 handler，也不把 STS2 的 C#、Godot、BaseLib 或 hook 写入通用领域接口。
- 行为代码优先检索当前版本真相源；历史 Markdown 示例不是跨版本权威答案。
- 当前只有 STS2 一个完整样本，不提前设计过度通用的 Game Pack schema。

### 3.6 Stage 2 目标分层

- 目标采用编译期分层的模块化单体，仍保持单仓库、单进程和统一发布。
- Feature 定义产品功能；Core Runtime 提供通用执行原语；Game Pack 提供游戏贡献；Truth Snapshot 提供当前版本事实；Resource Workspace 管理用户和 AI 资源。
- 目标责任域为 `ats-kernel`、`ats-runtime`、`ats-game-context`、`ats-workspace`、`ats-features` 和 `ats-adapters`；迁移完成后删除旧 `ats-core`。
- Game Pack 不携带任意可执行代码，只引用经过注册和测试的 provider、runner、indexer、validator 与 transformer。
- Feature Recipe、Pack Contribution、Truth Evidence、Selected Resources、Project Context 和 Runtime Custom Instructions 共同组成可复验的 run-scoped model request。
- 目标方案不代表当前代码已经完成拆分；每个 Work Order 完成后再同步现状和架构总览。

## 5. 完成标准

桌面 MVP 收口至少满足：

- 真实 single asset 主链能生成可编译、可打包、可在游戏中加载的产物。
- 行为、图片、本地化和 manifest 在真实游戏验收中达到可接受质量。
- 配置、鉴权、网络、知识、工具链和文件错误能指导用户修复或重试。
- baseline 安装版可完成基本工程和任务流程；ML 版本的准备、成功与降级行为明确。
- 双进程不能同时写入同一工程，退出后锁能正常恢复。
- 发布候选通过约定的 Rust、前端、Tauri 和关键 E2E 验证。
- 总览、现状、当前方案和实际代码保持一致。
- compile failure 不污染正式工程或 final Artifact，并能通过 diagnostic ID 找到脱敏的生成 bundle 与编译报告。
- Truth Snapshot 可变索引不默认落入仓库 watcher 范围；长期锁失败保持 typed 且不伪造瞬态成功。
- Stage 2 讨论前已有可审查的 STS2 耦合库存，且不把单一 STS2 样本误称为完整多游戏能力。
- Cargo DAG 能在编译期阻止 Runtime、Game Context 和 Workspace 反向依赖 Feature。
- 新 Feature 不修改 Runtime 中心结果枚举，Artifact Store 不直接依赖上层领域类型。
- 生产自然语言 Prompt、游戏 guidance、当前事实、用户偏好和结构化合同各有唯一所有者。
- 用户上传、AI 生成和 Pack 默认资源使用同一版本、验证、选择和发布流程。
