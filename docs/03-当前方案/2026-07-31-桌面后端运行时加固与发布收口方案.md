## 1. 结论

当前 Mod 生成核心已通过 Game Pack Stage 1 自动 E2E 和 STS2 真实游戏验收。桌面 MVP 剩余风险不在生成算法本身，而在产品运行层：

1. 结构化失败契约已经贯通 Core、RunRecord、Tauri 和 React。
2. `ProjectSession` 已统一持有工程 OS 锁、共享 Run repository、取消 token 和 task handles；关闭、切换和应用退出均先 cancel-and-drain。
3. cancel/success/failure 通过共享 repository CAS 竞争唯一终态，打开工程前会把遗留 Pending/Running reconciliation 为 `run.interrupted`。
4. LLM、ZIP、Truth Snapshot、图片 blocking work 和 Windows child process tree 已接入协作式取消；取消后的清理完成前不持久化 `Cancelled`。
5. baseline/ML 安装包缺少隔离构建目录、运行时 BuildInfo、构建 manifest 和图片处理 provenance，无法排除串包或证明安装版实际使用了 ML。
6. CI 只覆盖 Ubuntu/default feature，Windows、`ml-rembg`、Tauri bundle 和安装后启动尚未形成可重复的发布门禁。

本方案建议先收口错误契约和运行时正确性，再做安装版与发布验证。不在本阶段继续扩张 Game Pack Stage 2。

## 2. 目标与非目标

### 2.1 目标

- LLM、Image、Package 等失败通过统一、结构化、可脱敏的契约穿过 Core、Tauri、RunRecord 和 React。
- 关闭或切换工程时先停止接收新 Run，取消并等待全部后台 Run 收尾，再释放工程 OS 锁。
- `RunRecord` 在一个 CAS 聚合中保存执行状态、timeline、failure 和 result；取消不得被复活，终态事件不得重复。
- `ArtifactManifest` 随产物保存哈希、Game Pack/Truth Snapshot Evidence 和 processor provenance，不依赖可清理的 Run history。
- baseline 和 ML 安装包使用隔离构建目录，可区分、可哈希、可追溯；运行中应用能报告自己的 BuildInfo。
- Windows 发布候选从构建到安装验收有机器可读记录和明确停止条件。
- 旧 Python/FastAPI 架构文档被当前 Rust/Tauri 事实替换。

### 2.2 非目标

- 不接入第二个真实游戏。
- 不实现动态安装外部 Game Pack。
- 不完成多游戏 Settings/发现 UI 和通用 provider registry。
- 不追求 Web 与 Desktop 功能对等。
- 不引入数据库任务系统、事务型 Audit、自动更新、签名公证或依赖升级。
- 不恢复旧 Python/Web 平台主链。

## 3. 当前架构缺口

| 优先级 | 缺口 | 代码事实 | 影响 |
| --- | --- | --- | --- |
| P0 | 错误契约丢失 | Tauri 大量使用 `Result<T, String>`；`Job.error` 是 `String`；前端直接 `String(e)` | GUI 无法稳定区分配置、鉴权、限流、网络、上游和写盘失败 |
| P0 | 脱敏边界不统一 | LLM/Image 客户端会在无法解析时截取上游 body 作为错误消息 | 代理回显的敏感内容可能进入 GUI、history 或 audit |
| P0 | 工程关闭没有排空协议 | Job spawn 后只持有路径/repository；`close_project` 直接 drop `ProjectFolder` | 后台 Job 仍写旧工程时，第二进程已可获得 OS 锁 |
| P0 | Repository 锁作用域过小 | `FileJobRepository::new` 创建实例内锁，Tauri 每个 command 又重新构造实例 | cancel 和 handler 收尾不共享真正的读改写锁 |
| P0 | 终态收尾分裂 | common helper 已有 CAS，build/package/plan/log/batch 仍手写 `get -> update` | `Cancelled` 存在被并发收尾覆盖的风险 |
| P0 | 运行历史重复存储 | `AuditedJobRepository` 把 Job 状态迁移再写入 `.ats/audit.log`，且在 CAS 锁外读取旧状态 | 两份运行事实可能分叉，并发时可能重复或错误记录终态 |
| P1 | 进程崩溃恢复缺失 | Job 持久化到文件，但启动/打开工程时不处理遗留 `Pending/Running` | 异常退出后任务可永久显示 Running |
| P1 | ML 证据不足 | `ImageProcClient` 只返回 PNG 字节；prewarm 失败后没有显式重试命令 | 无法证明 ML 安装版实际使用 u2netp |
| P1 | 安装包变体无身份 | baseline/ML 共用 product name、identifier、version 和 bundle 目录，运行时不报告 BuildInfo | 产物可能混淆或覆盖，验收证据无法绑定实际二进制 |
| P1 | 发布矩阵不完整 | GitHub CI 只有 Ubuntu default feature；`build.ps1` 只列出 bundle 文件 | Windows/ML/installer 问题只能在人工收口时发现 |

## 4. 目标架构

### 4.1 错误流

```text
Provider / IO / Tool Error
           |
           v
Domain-specific error
           |
           v
FailureNormalizer + Redactor
           |
           v
ActionableFailure
  code / category / stage / message
  action / retryable / retry_after
  diagnostic(redacted)
           |
           +--> Tauri CommandFailure --> React ActionableErrorNotice
           |
           +--> RunRecord.failure --> history / progress
```

### 4.2 工程会话与 Run

```text
ActiveProject
     |
     v
Arc<ProjectSession>
  + ProjectFolder / OS lock
  + Arc<RunRepository>
  + RunTaskScope / cancellation registry
  + game_id / Pack
  + lifecycle state: open | closing
     |
     +--> RunLease --> spawned Run
     +--> RunLease --> build/package child process

UI close/switch:
  mark session closing and reject new runs
  request cancellation for every active run
  await stream/file transaction/child process cleanup
  release OS lock and clear ActiveProject only after drain succeeds
  remain closing and keep the lock if any run cannot stop safely
```

关闭/切换后 Run 不得继续执行，因此不建立 detached/draining session registry。UI 在排空期间保持工程上下文，只显示 `closing` 状态并禁止新提交。

### 4.3 两个权威聚合

```text
RunRepository
  RunRecord
    id / operation / status / progress
    failure / result / attempts
    timeline[]
      created / started / cancel_requested
      cancelled / failed / succeeded
                       |
                       +--> artifact_manifest_ref + manifest_sha256

Artifact Store
  artifacts/<artifact-id>/runs/<run-id>/
    artifact-manifest.json
    files/                    # 本次成功产物的不可变快照

ArtifactManifest
  artifact files + SHA-256
  published project-relative paths
  Game Pack / Truth Snapshot Evidence
  generation parameters
  processor / model provenance
  producing_run_id

Diagnostic Logger
  .ats/diagnostics/<run-id>/
  structured runtime diagnostics
  non-authoritative / redacted / disposable
```

- `RunRecord` 是执行真相；状态和 timeline 在同一次 repository CAS 中更新。
- `ArtifactManifest` 是产物真相；每次成功 Run 使用独立 `run-id` 目录，发布后不可变，随工程和产物保留，不随 Run history 清理。
- 删除独立业务 `AuditSink`、`AuditedJobRepository` 和 `.ats/audit.log` 写入链；非 Run 操作只进入结构化诊断日志或各自的配置/manifest 真相源。

### 4.4 安装版与 ML 证据

```text
build.ps1
  +--> baseline --> isolated target/bundle --> release/<version>/baseline/
  +--> ml-rembg -> isolated target/bundle --> release/<version>/ml-rembg/
                         |
                         v
              release-manifest.json
              commit / version / variant
              features / build_id / artifact sha256

Running application
  BuildInfo
    commit / variant / features / build_id

ImageProcOutcome
  bytes
  processor: u2netp | simple
  model_sha256
  runtime_version
  fallback_used / fallback_reason
```

## 5. 已确认决策

### Gate A - RunRecord schema v2 采用破坏性切换

不迁移旧 Job history，也不长期兼容 V1/V2。

- 新模型命名为 `RunRecord`，只写 `failure: Option<ActionableFailure>`，不保留 `error: String` 第二真相源。
- Core 类型/repository/service、Tauri command/event、TypeScript 类型/hook 全链路从 `Job` 破坏性改名为 `Run`，不保留旧 API 或类型别名；产品中文仍使用“任务”。
- Run JSON 增加 `schemaVersion = 2`，并纳入 `timeline` 和结构化 `result` 引用。
- 首次打开含 V1 history 的工程时，在持有 OS 锁后把整个目录重命名为文件系统安全的 `history.v1-backup-YYYYMMDDTHHMMSSZ`，再建立空的 V2 `history/`；任一 JSON 无法解析或缺少 `schemaVersion = 2` 即按整目录 V1 处理，不逐条转换、不静默删除。
- V1 备份和 `<runtime>/knowledge/jobs` legacy history 不进入产品查询和取消路径，只用于用户手工取回历史证据。

### Gate B - 关闭或切换工程必须取消并排空 Run

- session 进入 `closing` 后拒绝新 Run。
- 对全部活动 Run 发出取消，并等待 LLM stream、文件事务和外部 child process 完全停止。
- 排空成功后才能清除 `ActiveProject` 并释放 OS 锁。
- 排空等待上限为 30 秒；超时后 UI 保持 `closing`，显示阻断 Run 和当前阶段，只允许重试取消或退出应用。
- 无法可靠终止的 child process 必须继续持锁；不提供“强制释放工程锁”，不得后台继续执行后立即切换工程。

### Gate C - baseline/ML 保持同一产品身份，但构建完全隔离

- 保持同一 Tauri identifier，不支持并排安装。
- variant 使用独立 target/bundle 目录，禁止从共享目录枚举残留文件。
- 候选文件通过 variant 路径、BuildInfo 和 SHA-256 区分；验收时先卸载一个 variant 再安装另一个。

### Gate D - 运行历史与产物证据分离

- 删除独立业务 Audit；Job 生命周期合并进 `RunRecord.timeline`。
- Evidence 只存在于不可变 `ArtifactManifest`，Run 终态只保存 `artifact_manifest_ref` 和 `manifest_sha256`。
- 不再生成 `evidence.md` 或其他人类可读 Evidence 副本；Core、GUI 和验收工具只读取结构化 manifest。
- 既有 `evidence.md` 不做跨工程批量删除；同一 artifact 首次按新结构成功发布时，在文件事务内移除旧共享目录中的陈旧副本，避免它继续被误认为当前证据。
- 结构化诊断日志是非权威、可清理数据，不参与 Run 或 Artifact 的一致性判定。
- 已存在的 `.ats/audit.log` 留在原位但不再读取或追加，方案不自动删除用户历史文件。

### Gate E - 路径按输出边界分层脱敏

- 工程内路径保存为相对路径；工程根、游戏根、用户目录和临时目录分别标准化为 `$PROJECT`、`$GAME_ROOT`、`$USER_HOME` 和 `$TEMP`。
- 用户主动配置的完整工具路径只允许在当前本地 GUI 上下文显示；持久化 history、manifest 和导出报告使用标准化路径。
- URL 删除 user-info、query 和 fragment；token、Authorization、Cookie、完整 Prompt、完整模型输出和上游原始 body 不进入任何错误层。
- 文件名、相对路径、稳定错误码和必要的 IO kind 保留，以保证错误可行动。

#### RunRecord v2 最小结构

```text
RunRecord
  schemaVersion = 2
  id = run-...
  kind
  status = pending | running | succeeded | failed | cancelled
  createdAt / startedAt / completedAt
  payload
  progress
  failure: ActionableFailure?
  result: RunResult?
  attempts
  timeline: RunTimelineEvent[]

RunTimelineEvent
  kind = created | started | cancel_requested
       | succeeded | failed | cancelled | interrupted
  at
  stage?
  failureCode?
  cancellationReason? = user | project_close | project_switch | app_shutdown
```

- 本阶段 `payload` 保持按 `RunKind` 校验的受控 JSON；`RunResult` 使用 tagged enum，不继续使用任意 JSON。
- progress 更新不写 timeline；重复取消请求不得重复追加 `cancel_requested`。
- `interrupted` 是崩溃恢复事件，对应最终 `status = failed` 和 `failure.code = run.interrupted`。
- `cancelled` 是预期终止，不写 `failure`；取消来源只记录在 timeline 的 `cancellationReason`。
- terminal CAS 必须同时提交 status、completedAt、failure/result 和 terminal timeline event。

#### 状态转换矩阵

| 当前状态 | 允许目标 | timeline |
| --- | --- | --- |
| 新建 | `pending` | `created` |
| `pending` | `running` | `started` |
| `pending` | `cancelled` | `cancel_requested`、`cancelled` |
| `running` | `succeeded` | `succeeded` |
| `running` | `failed` | `failed` 或恢复专用 `interrupted` |
| `running` | `cancelled` | `cancel_requested`、`cancelled` |
| 任一终态 | 无 | 拒绝修改 |

#### ArtifactManifest 最小结构

```text
ArtifactManifest
  schemaVersion = 1
  artifactId / artifactKind / producingRunId / createdAt
  gameContext
    gamePackId / gamePackSchemaVersion / gamePackSha256
    snapshotId / snapshotSchemaVersion / sources / indexes / toolVersions
  evidence[]
    source / symbol / purpose / boundedExcerpt
  generation
    provider / model / inputsSha256
  imageProcessing?
    processor / modelSha256 / runtimeVersion / fallback
  files[]
    role / snapshotRelativePath / publishedRelativePath?
    byteLength / sha256
```

- `artifactId` 和 `run-id` 必须是无分隔符、无遍历、无符号链接跳转的安全单段；manifest、Evidence 和所有路径不得包含凭据、完整 Prompt、完整模型输出或未标准化绝对路径。
- 只有成功发布的产物生成 manifest；失败 Run 的 raw/compile/image diagnostics 写入 `.ats/diagnostics/<run-id>/`，属于可清理诊断，不伪装为正式 ArtifactManifest。
- 同一 artifact 的后续成功 Run 新建独立 `run-id` 目录，不覆盖旧 manifest 或快照；本阶段不自动清理成功 Artifact Store。
- 先在同一文件事务中发布产物和 manifest，再以 `artifact_manifest_ref + manifest_sha256` 完成 Run。

#### 停止条件

- Run 状态与 timeline 不能在同一次 CAS 中提交时停止。
- 任一产品路径仍读写 `.ats/audit.log`、legacy Job history 或新 `evidence.md` 时不得验收。
- 任一产物成功但没有可验证 ArtifactManifest，或 Run result 复制了另一份 Evidence 时不得验收。
- V1 history 备份失败时拒绝进入可写 session，不部分迁移、不静默清空。

### Work Order 2 - 结构化错误契约

> 实施进度（2026-07-31）：Work Order 2 已完成。Core 建立唯一 `ActionableFailure`、typed normalizer、白名单 context 和脱敏 diagnostic；Run handler、全部生产 fallible Tauri commands、LLM stream、统一 invoke guard 与 React 错误视图已迁移。未知错误固定落 `core.unclassified`，不对外调用原始 `Display`。Core/Desktop/TypeScript 与前端定向验证通过；ProjectSession 行为仍留在 Work Order 3。

#### 修改范围

- 在 Core 完成 `FailureCategory`、`RecoveryAction`、`FailureNormalizer` 和路径/秘密脱敏器。
- 为 `LlmError`、`ImageGenError`、package/filesystem 失败建立稳定映射，不把 provider 原始 body 直接对外。
- 所有 Tauri command 返回可序列化 `CommandFailure`；首批领域映射覆盖 LLM、Image、Package、Project、Toolchain、ImageProc 和 Run，其余未知错误统一落到 `core.unclassified`，不再裸传字符串。
- Web 壳可将同一契约映射为 HTTP，但本轮不补齐 Web 功能。
- React 建立统一 `ActionableErrorNotice`，不再由各页自行拼接 `String(e)`。

#### ActionableFailure 最小结构

```text
ActionableFailure
  schemaVersion = 1
  code
  category = configuration | authentication | rate_limit | network
           | upstream | validation | filesystem | toolchain
           | state | internal
  stage
  message
  action = configure | reauthenticate | retry | check_path
         | install_dependency | open_settings | none
  retryable
  retryAfterMs?
  context?          # 只允许字段白名单和标准化路径
  diagnostic?
    id
    summary         # 已脱敏、有限长度
    ioKind?
```

- `CommandFailure` 与 `RunRecord.failure` 序列化同一 `ActionableFailure`，不建立第二套字段映射。
- `diagnostic` 不保存原始 error/body/header/Prompt；未知错误通过 `core.unclassified` 返回 diagnostic ID 和安全摘要。

#### 停止条件

- 错误 schema 只能用字符串 message 表达重要分支时停止。
- 脱敏后无法保留足够诊断信息时停止并调整 diagnostic 边界。
- 不得为了兼容旧前端长期同时维护两套错误契约。
- 任一 Tauri command 仍可把未知错误裸字符串直接暴露给前端时不得验收；允许通过统一 `core.unclassified` 安全兜底。

- 提交后台 Run 时注册 `RunLease` 和 cancellation handle，直到 handler 完全退出。
- 将 build/package/plan/log/batch 收尾改为共享 CAS helper；CAS 内同时形成唯一 timeline 终态事件。
- 明确取消语义：LLM stream drop；文件写入回滚；外部 child process 必须可终止并等待退出。
- `close_project/switch_project` 执行 `open -> closing -> drained`：拒绝新 Run、取消全部活动 Run、等待清理，完成后才释放 OS 锁。
- cancel-and-drain 超过 30 秒返回结构化 `project.close_timeout`，session 继续保持 closing 和 OS 锁；后续只接受重试取消或应用退出。
- 正常应用退出复用同一取消与 child process tree 终止能力；外部强制结束进程后的未完成 Run 由下次打开 reconciliation 标记 interrupted。
- 打开 session 时对遗留 `Pending/Running` Run 执行 reconciliation。
- 同步更新 ADR 0003 的 Tauri shutdown 契约，替换“没有显式 cleanup hook”的旧事实。

#### 恢复规则

```text
Pending/Running + 上一进程已消失
  -> Failed
  -> failure.code = run.interrupted
  -> 保留原 payload/progress/attempts
  -> timeline 追加唯一 interrupted 事件
```

#### 停止条件

- 任何关闭/切换路径能在 Run 存活时释放 OS 锁，不得进入验收。
- 任何 handler 绕过共享 terminal CAS 直接更新终态，不得进入验收。
- 任何 Run 进入终态却没有对应唯一 timeline 事件，或同一终态事件出现两次，不得进入验收。
- 外部构建进程无法可靠终止并等待退出时，工程必须保持 closing 和 OS 锁，不得切换到其他工程。

### 8.1 Good / Base / Bad 场景

- Good：asset Run 从 `pending -> running -> succeeded`，timeline 各事件恰好一次；产物与 `artifacts/<artifact-id>/runs/<run-id>/artifact-manifest.json` 在同一事务发布，Run result 的 manifest SHA-256 可复算。
- Good：关闭工程时活动 LLM/文件/child process Run 在 30 秒内全部取消并回滚，随后释放 OS 锁，第二进程才可打开工程。
- Base：工程只有 V1 Job JSON；打开时整体重命名为 `history.v1-backup-YYYYMMDDTHHMMSSZ`，建立空 V2 history，旧 audit/evidence 文件不进入产品查询。
- Base：关闭工程时只有全局 ML prewarm；工程可以关闭，prewarm 继续且不访问工程目录。
- Bad：cancel 与 handler completion 同时到达；只能有一个 CAS 赢得终态，状态、completedAt 和 terminal timeline 不得分叉或重复。
- Bad：ArtifactManifest 或任一声明文件写入失败；文件事务回滚，Run 不得进入 succeeded，也不得留下新的 `evidence.md`。
- Bad：cancel-and-drain 超过 30 秒；返回 `project.close_timeout`，保持 closing 和 OS 锁，第二进程仍被拒绝。
- Bad：上游错误包含 token、URL query、原始 body 或用户目录；Tauri、RunRecord、manifest、诊断日志和导出内容均不得出现 canary 原文。

## 10. 风险与控制

| 风险 | 控制 |
| --- | --- |
| RunRecord v2 使旧 history 不可读 | 在持有工程 OS 锁时整体重命名 V1 history 为只读备份；不混读、不逐条迁移、不静默删除 |
| 错误契约演化为过重通用框架 | 发布关键领域使用稳定码，其余通过一个 `core.unclassified` 安全兜底，不为未出现领域预测分类 |
| closing 长时间不结束 | UI 显示正在停止的 Run ID 和阶段；设定取消超时后继续持锁并报告明确阻断，不伪装关闭成功 |
| child process 无法立即取消 | 必须实现进程终止并等待；失败时保持 session、工程锁和 closing 状态 |
| RunRecord 与 ArtifactManifest 发布顺序分叉 | 先在文件事务中发布不可变产物快照、工程输出和 manifest，再以 digest 完成 Run；重开时对已发布 manifest 与非终态 Run 做 reconciliation |
| Artifact Store 持续增长 | 本阶段不自动删除成功证据；UI 后续清理必须按完整 run-id 目录操作，并先检查没有 RunResult/current artifact 引用 |
| history 写盘失败导致 UI 与磁盘不一致 | Run 状态不声称已持久化；当前会话保留内存失败、GUI 告警和 best-effort 脱敏诊断；重开时只能根据已发布 ArtifactManifest 恢复可观察事实，不能承诺恢复未落盘 Run |
| ML 网络下载使安装验收不稳定 | 固定 URL/hash，支持续传/超时/重试，清楚区分首次下载和缓存命中 |
| 发布验证过重导致日常迭代变慢 | 定向测试常态化；完整 installer 仅在候选门禁运行 |

## 13. 已审阅结论与启动门禁

已于 2026-07-31 确认：

1. 关闭或切换工程后 Run 不应继续执行，采用 cancel-and-drain，不采用 detached session registry。
2. 删除独立业务 Audit；RunRecord 合并状态、timeline、failure 和 result，ArtifactManifest 独立保存产物 Evidence。
3. 旧 Job history 不值得迁移；采用可恢复的整目录备份和 V2 空历史，不保留兼容读取。
4. 路径采用分层脱敏：本地 GUI 保留必要可行动路径，持久化和导出边界使用相对路径或标准根占位符。
5. baseline/ML 保持同一应用身份，但使用隔离构建目录、嵌入 BuildInfo，并与 release manifest/provenance 交叉核对。
6. `ProjectSession` 与 Run 并发正确性必须在安装版验收之前完成。
7. 不保留 `evidence.md`；`ArtifactManifest` 是唯一证据文件，GUI 需要时直接渲染其结构化内容。
8. Core、Tauri、TypeScript 和持久化模型全面从 `Job` 破坏性改名为 `Run`，不保留兼容 API；中文 UI 仍称“任务”。
9. cancel-and-drain 等待上限为 30 秒；超时后保持 closing 和 OS 锁，只允许重试取消或退出应用。
10. `cancelled` 是预期终态而不是失败；`RunRecord.failure` 保持为空，取消来源进入 timeline。
11. Artifact Store 按 `artifact-id/run-id` 保存不可变成功快照；失败诊断进入可清理的 `.ats/diagnostics/<run-id>/`。
12. ML prewarm 是不读写工程的全局 runtime operation，不受关闭工程影响。

开始实现前，先创建并只激活 `07-31-run-artifact-contract` Trellis 任务。该任务 PRD 必须把 RunRecord v2 字段、状态迁移、timeline 事件、ArtifactManifest schema/发布顺序、Audit/evidence.md 移除、旧 history 备份行为和定向测试逐项写成可执行验收条件。
