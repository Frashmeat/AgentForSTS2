## 3. mod_template ↔ Rust codegen 联动

仓库根 `mod_template/` 是 dotnet 工程脚手架。`§2.2` 走完后已经生成了 .cs，
但**它真能编译出 .dll 吗** —— 这是计划 §7.2 #6 标待验证的核心。

### 3.1 前置

```powershell
dotnet --version          # 期望 6.0 或 8.0+；没有先装 .NET SDK
# 如果有 STS2 安装：找到 sts2.dll / godot 路径
$STS2 = "C:\Program Files (x86)\Steam\steamapps\common\Slay the Spire 2\data_sts2_windows_x86_64"
Test-Path "$STS2\sts2.dll"
```

### 3.2 真跑 dotnet publish

```powershell
cd <你的项目根>          # §2.2 第 2 步创的那个
# 看 csproj 怎么引用 STS2 dll
notepad .\<csharp_name>.csproj
# 期望 ProjectReference / Reference 指向 sts2.dll 真实路径
# 如果是相对路径（如 ..\sts2.dll），把 sts2.dll 拷过去 OR 改成绝对路径

dotnet restore
dotnet publish -c Release
```

| 步骤 | 预期 |
| --- | --- |
| `dotnet restore` | nuget 包恢复成功（如果有 nuget.config 指向 cache，应秒过） |
| `dotnet publish` | bin/Release/net6.0/publish/ 出现 `<csharp_name>.dll`（含本轮 §2.2 生成的 `<Name>.cs` 编进去） |
| 用 dnSpy / ilspycmd 反编译 `<csharp_name>.dll` | 看到我们生成的 class（例如 `FlameRelic : Relic`） |
| 把 publish/ 内容拷进 STS2 mods 目录 → 启动游戏 → 进战斗 | 我们生成的遗物 / 卡片在游戏里能用 |

**反向验证**（任何一项失败都是 §7.2 #6 仍然 🟡）：

| 症状 | 可能根因 |
| --- | --- |
| `<Name>.cs` 不在 csproj 的 compile 列表 | mod_template 的 csproj 是 SDK-style `<Compile Include="**/*.cs" />` 吗？检查 |
| 命名空间不匹配 / using 缺失 | code_generate handler 写 .cs 时没参考 mod_template 的 namespace 约定 |
| 编译报 `CS0246: 找不到 Relic 类` | 没引到 sts2.dll；或者引到了但路径错 |
| publish 成功但游戏没识别 | ModId / project.godot 没改对（v2 §1.1 已验过模板替换，但游戏侧识别逻辑要看） |

把症状 + csproj + .cs + 完整 publish 输出收集起来：

```powershell

```
