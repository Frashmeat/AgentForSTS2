### 2.5 ML rembg prewarm（feature ml-rembg 时才真测）

#### 2.5.1 feature off（默认）

```powershell
.\dev.ps1
# 或 cargo tauri build（不带 --features）
```

| 步骤 | 预期 |
| --- | --- |
| Dashboard Audit chip | `ML rembg: fallback — ml-rembg feature disabled at build time`（灰边） |
| HealthCard 第 4 行 | `○ ML 背景去除就绪`（不亮） |
| asset_generate 跑 | 走启发式 SimpleBgRemover；`.rembg.png` 仍然出，但深色背景效果差 |

#### 2.5.2 feature on

```powershell
cargo tauri build --features ml-rembg
# 跑产出的 .exe（target/release/agentthespire.exe 或 bundle 目录里）
```

| 步骤 | 预期 |
| --- | --- |
| app 启动 1-3s 内 | AuditCard chip 显示 `ML rembg: loading — downloading u2netp.onnx (~5MB)`（黄边） |
| 网好的话 ~5-30s 后 | chip 变 `ML rembg: ready (u2netp.onnx)`（绿边）；HealthCard 第 4 行变 `✓` |
| `%APPDATA%\AgentTheSpire\models\` | 出现 `u2netp.onnx` 文件 |
| 再跑一次 app | 缓存命中，chip ~1s 内变 ready |
| asset_generate 出图（带深色 / 复杂背景的 prompt） | `<Name>.rembg.png` 的 alpha mask 应该比启发式版本明显更精确 |
| 网络断开第一次跑 | chip 显示 `ML rembg: fallback — model download: ...`，asset_generate 走启发式不报错 |

**反向验证**：如果 chip 永远 loading 不变 ready，看 Tauri devtools console 的 backend log 有没有 ort init 错误（可能是 onnxruntime 静态链接失败，或 DirectML.dll 缺失 —— Win10 1903 以下不带，从 `%LOCALAPPDATA%/ort.pyke.io/dfbin/.../onnxruntime/lib/DirectML.dll` 拷到 .exe 旁）。

### 2.11 Settings 热替换编辑（commit `fe89016`）

LLM / image_gen 字段可在 UI 内表单编辑 + 保存即热替换，无需重启 app。

| 步骤 | 预期 |
| --- | --- |
| 左侧导航点 "Settings" 进 `/settings` | LLM / image_gen / Runtime 三段只读视图 |
| 右上点 "Edit" | LLM + image_gen 段变成表单（provider/model/base_url/api_key 各输入框）；右上变 Save + Cancel |
| api_key 输入框 placeholder | `(已配置 — 留空保持原值)` 或 `(未配置)`；留空 → 不动；输入 = 替换 |
| 改 provider + model + Save | 横幅显示 "✓ 已保存并热替换（无需重启）"；列表回只读模式；config.json 文件被原子写回 |
| 立刻在 Dashboard 提交 text_generate | **应该用新 model** —— build_llm_client 每次都 snapshot settings，不缓存 |
| 改完保存 → Cancel Edit | 之前未保存的编辑丢弃，回到 snapshot 值 |
| 改完 → 没改任何字段 → Save | 提示 "没有改动"（patch 空） |
| api_key 故意填错 → Save 成功 → 提交 job | LLM 返回 401，UI 暴露错误。再点 Edit 改回正确 key + Save → 立刻能跑 |
| 在 OS 编辑器手动改 config.json + Reload 按钮 | UI 读到外部改动 |

**反向**：以前要重启 app 才生效；现在 hot-reload 应当 < 100ms。

### 2.12 边界：保存失败路径

| 场景 | 预期 |
| --- | --- |
| config.json 文件被外部锁（编辑器打开 + 锁） | Save 返回 `write config: ...` 错误；内存 settings 不变（旧值仍可用） |
| 把 LLM api_key 改空再 Save | 保存成功，api_key_configured 变 ○；下次 build_llm_client 失败 → asset/code generate handler 立刻 401 / config error |
| Settings 页打开同时多 job 跑 | 不阻塞；RwLock 读写互斥但 clone 即释放 |

## 3. 边界用例（每 handler 顺手）

| 场景 | 预期 |
| --- | --- |
| 中途按 Cancel | 流式 5 秒内真断网；Job 进 Cancelled；audit 一条 `job.cancelled` |
| api_key 故意填错 | 401 错误清晰回 UI；Job Failed；audit `job.failed` data.error = "401 ..." |
| 工程路径含中文（如 `D:\我的项目\卡片1`） | 所有 .cs / .png / .json 写入正常；audit.log 也能写 |
| 工程路径 > 260 字符 | 走 `\\?\` 长路径模式不崩 |
| 同一工程开两个 Tauri 实例 | 第二个报 `Locked` 错而非互相覆盖 |
| 删掉 `%APPDATA%\AgentTheSpire\models\u2netp.onnx` 后重启 app | feature on 时重新下载 + 缓存命中 |

## 4. 报 bug 流程（与 v1 一致）

1. 复现 → 不关 Tauri 窗口（保留 devtools console）
2. 跑收集脚本：
   ```powershell
   .\scripts\collect-bug-report.ps1 -ProjectRoot <工程根> -OutDir .\bug-reports
   ```
3. 提 GitHub issue，标题：`[smoke-v2] <handler/page> - <症状>`
4. 附 zip + console panic 段（如果有）+ **AuditCard 截图**（这次能看到 audit 自动写的事件，对定位很有帮助）

## 5. 收 bug 后能看到什么（v2 增量）

v1 已经能拿到 audit / history / config-redacted。v2 新增信息：

- `.ats/audit.log` 现在**自动写入**每个 job 的生命周期 —— 不用手动 emit
- `image_proc_status` Tauri command 可单独查（在 console 跑 `await __TAURI__.core.invoke("image_proc_status")`）
- HealthCard 的 readiness 字段会让用户先自检"哪个灯不亮"，bug report 价值更高
