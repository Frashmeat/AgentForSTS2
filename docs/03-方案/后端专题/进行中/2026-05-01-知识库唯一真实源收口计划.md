# 知识库唯一真实源收口计划

> 文档定位：定义 Workstation 与 Web 知识库目录的唯一真实源规则，并记录移除旧 seed、旧目录和多来源兜底的破坏性收口计划。
>
> 事实依据：基于 2026-05-01 对 `knowledge_runtime.py`、Docker Compose、Web 管理端知识库包、release 打包脚本与当前目录结构的调查。
>
> 权威入口：上级入口为 `docs/03-方案/后端专题/README.md`。
>
> 最后更新：2026-05-01
>
> 当前状态：进行中

## 当前理解

项目尚未上线，允许破坏性变更。后续不再保留“旧目录兼容、seed 自动补全、轻量参考文件伪装知识库、release 产物副本并存”等包袱。

当前知识库来源存在多个口径：

- `runtime/knowledge/`：当前本地运行时知识库主目录。
- `runtime/knowledge/packs/`：Web 管理端上传知识库包的存放目录。
- `backend/app/modules/knowledge/resources/sts2/`：内置资源文档 seed。
- `backend/agents/sts2_api_reference.md`：旧游戏 API 参考 seed。
- `backend/agents/baselib_src/BaseLib.decompiled.cs`：旧 BaseLib seed。
- 根目录 `knowledge/`：当前代码不应再读取的旧残留目录。
- `game_decompiled` / `baselib_decompiled`：旧目录名，当前主线不应继续使用。
- `tools/latest/artifacts/*/runtime/knowledge/`：release 产物副本，不是源码主线。

当前 Docker Compose 还存在运行时目录挂载不一致问题：容器内知识库更新结果没有明确收口到唯一持久化的 runtime 目录。

## 目标

每个运行实例只允许一个知识库真实源：

```text
<运行时目录>/knowledge
```

本地仓库实例：

```text
F:\WebCode\AgentForSTS2\runtime\knowledge
```

Docker Workstation：

```text
/app/runtime/knowledge
```

Docker Web：

```text
/app/runtime/knowledge
```

Web 管理端知识库包属于 Web 实例自己的运行时包仓库：

```text
<web runtime>/knowledge/packs/<pack_id>/content
```

它不再被解释为 Workstation 的另一个知识源。Workstation 只读写自己的 `<workstation runtime>/knowledge`。

## 不再保留

- 不再从 `backend/agents/sts2_api_reference.md` 自动补到 `runtime/knowledge/game/`。
- 不再从 `backend/agents/baselib_src/` 自动补到 `runtime/knowledge/baselib/`。
- 不再从 `backend/app/modules/knowledge/resources/sts2/` 自动补到运行时目录，除非后续明确把它改造成构建期模板，而不是运行时真实源。
- 不再把 `sts2_api_reference.md` 视为完整游戏反编译源码。
- 不再支持 `runtime/knowledge/game_decompiled/` 与 `runtime/knowledge/baselib_decompiled/`。
- 不再要求 release 包初始自带轻量知识库；没有完整知识库时应显示 `missing`。
- 不再把根目录 `knowledge/` 当作任何运行时入口。

## 计划

1. 统一运行时目录解析
   - 明确 `knowledge_runtime.py` 的知识库根目录只来自当前实例 runtime 根。
   - 本地、Docker、release 都指向 `<runtime>/knowledge`。

2. 收口 `ensure_runtime_knowledge_seeded`
   - 改为只创建目录结构。
   - 不复制任何 seed 文件。
   - 若缺少 `game/**/*.cs` 或 `baselib/BaseLib.decompiled.cs`，状态就是 `missing`。

3. 移除 active pack 对 Workstation 的影响
   - Workstation 不再通过 active pack 切换知识源。
   - Web 管理端 active pack 作为包管理指针；激活时把包内容安装到当前 Web 实例自己的 `runtime/knowledge/`。
   - 后端运行时读取始终只走当前实例的 `runtime/knowledge/`。

4. 调整知识库状态判定
   - `game/**/*.cs` 达到完整性门槛才算游戏源码可用。
   - `BaseLib.decompiled.cs` 存在才算 BaseLib 可用。
   - 只有资源 md 或 API 摘要时不得标记为完整知识库。

5. 修 Docker 挂载
   - `docker-compose.workstation.yml` 挂载持久 runtime 到 `/app/runtime`。
   - `docker-compose.web.yml` 挂载持久 runtime 到 `/app/runtime`。
   - Docker 更新知识库后必须落在 `/app/runtime/knowledge`。

6. 修 release 打包脚本
   - `tools/latest/package-release.ps1` 不再复制旧 seed 到 `runtime/knowledge`。
   - release 只创建空 runtime 目录与必要工具。
   - 完整知识库由用户运行“更新知识库”生成，或通过 Web 管理端上传完整包。

7. 清理旧目录与文档口径
   - 删除或停止引用根目录 `knowledge/`。
   - 删除或停止引用 `game_decompiled`、`baselib_decompiled`。
   - 文档统一使用 `runtime/knowledge/game`、`runtime/knowledge/baselib`、`runtime/knowledge/resources/sts2`、`runtime/knowledge/packs`。

8. 更新测试
   - 调整依赖 seed 自动复制的测试。
   - 增加 Docker/runtime 目录解析测试。
   - 保留残缺知识库包拒绝上传测试。
   - 保留 Web 知识库包上传、激活、回滚、删除测试。

## 风险

- 现有残缺 `runtime/knowledge` 会被判定为 `missing`，需要重新执行“更新知识库”。
- Docker 用户需要重新创建或迁移 runtime volume。
- 旧 release 产物内的知识库副本不再有参考价值，需要重新打包。
- 如果还有旧代码直接 import `backend/agents/sts2_guidance.py`，需要同步迁到 `app.modules.knowledge` 下的新入口。

## 验收标准

- 代码搜索不到有效逻辑引用 `game_decompiled` / `baselib_decompiled`。
- 代码不再从 `backend/agents` 自动补知识库文件。
- Workstation 的知识库真实源只有 `<workstation runtime>/knowledge`。
- Web 管理端的知识库包真实源只有 `<web runtime>/knowledge/packs`。
- Docker Workstation 更新知识库后，结果持久化到 `/app/runtime/knowledge`。
- Docker Web 上传知识库包后，结果持久化到 `/app/runtime/knowledge/packs`。
- 没有完整 `game/**/*.cs` 的知识库继续被拒绝导出或上传。
- `backend/tests/test_knowledge_runtime.py` 通过。
- `backend/tests/platform/routers/test_platform_admin_http.py` 通过。
- `frontend npm run typecheck` 通过。

## 实施记录

- 已为后端引入 `SPIREFORGE_RUNTIME_DIR`，Docker 容器显式使用 `/app/runtime` 作为 runtime 根。
- 已将 `ensure_runtime_knowledge_seeded()` 收口为只创建目录，不再复制仓库内 seed。
- 已将运行时状态、导出、lookup/guidance/facts 入口统一到当前实例 `runtime/knowledge/`。
- 已将 Web 知识库包激活改为安装到当前 Web 实例 `runtime/knowledge/`，`packs/` 仅保留包仓库和元数据。
- 已将 `package-release.ps1` 改为初始化空知识库目录，不再复制旧 seed。
- 已物理删除根目录 `knowledge/`、`backend/agents/sts2_api_reference.md`、`backend/agents/baselib_src/` 与 `backend/app/modules/knowledge/resources/sts2/`。
