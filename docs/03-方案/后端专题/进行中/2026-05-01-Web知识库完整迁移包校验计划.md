# Web 知识库完整迁移包校验计划

> 文档定位：定义管理站上传、导出、激活知识库包时的完整包契约，确保 Web 工作站知识库同时包含反编译代码和规则文档。
>
> 事实依据：基于 2026-05-01 对 `knowledge_runtime.py`、管理端知识库包页面、平台管理接口和现有测试的调查。
>
> 权威入口：上级入口为 `docs/03-方案/后端专题/README.md`。
>
> 最后更新：2026-05-01
>
> 当前状态：进行中

## 当前理解

项目已收口为“一个运行实例只有一个知识库真实源”：当前实例的 `<runtime>/knowledge`。Web 管理端的 `packs/` 只保存上传包和元数据，激活时必须把包内容安装到当前 Web 实例自己的 `runtime/knowledge/`。

管理员上传知识库包不能只上传文档或只上传代码。该包应是完整 runtime knowledge 迁移包，至少包含：

- `game/**/*.cs`：游戏 `sts2.dll` 的完整反编译 C# 源码，数量达到完整性门槛。
- `baselib/BaseLib.decompiled.cs`：BaseLib 的反编译 C# 源码。
- `resources/sts2/*.md`：当前 Prompt 依赖的规则、摘要和规划文档。

## 目标

- 上传 zip 时拒绝残缺知识库包。
- 从本机 Workstation 导出时，如果当前 runtime 不完整，直接失败并给出可行动错误。
- 激活旧包或手工放入的包时再次校验，避免残缺包覆盖 Web runtime。
- 管理端页面明确展示缺少 BaseLib 或必需资源文档的原因。
- 文档统一说明知识库包是完整迁移包，不再暗示只要 `game/**/*.cs` 足够即可。

## 影响范围

- 后端知识库运行时：`backend/app/modules/knowledge/infra/knowledge_runtime.py`
- 平台管理接口测试：`backend/tests/test_knowledge_runtime.py`、`backend/tests/platform/routers/test_platform_admin_http.py`
- 管理端前端：`frontend/src/pages/admin/AdminKnowledgePacksPage.tsx`、`frontend/src/shared/api/admin.ts`
- 文档：`README.md`、`tools/README.md`、`docs/02-现状/当前前后端接口文档.md`、`docs/03-方案/后端专题/README.md`

## 风险

- 已存在的旧知识库包如果缺少 BaseLib 或必需资源文档，将无法再次激活。
- 当前本机或 Docker runtime 如果只有反编译代码没有 `resources/sts2/*.md`，导出会失败，需要先补齐完整知识库。
- 前端列表可能遇到旧包 metadata 缺少新增字段，因此新增字段必须保持可选展示。

## 验收标准

- 上传包缺少 `game/**/*.cs`、`baselib/BaseLib.decompiled.cs` 或任一必需 `resources/sts2/*.md` 时返回 400。
- 导出当前 Workstation runtime 时执行同一套完整性校验。
- 激活包前执行同一套完整性校验，不允许残缺包安装到 Web runtime。
- 管理端页面能看到源码统计、BaseLib 是否存在、必需资源文档缺失列表。
- API 文档说明新增 metadata 字段和完整包目录结构。
- 定点后端测试和前端 typecheck 通过。

## 实施步骤

1. 在 `knowledge_runtime.py` 定义必需资源文档清单和统一校验函数。
2. 扩展知识库包 metadata：记录 `has_baselib_file`、`has_required_resources`、`missing_resource_files`。
3. 将上传、导出、激活统一接入完整包校验。
4. 更新管理端类型和页面提示，避免只提示“缺游戏源码”。
5. 更新测试构造，让测试包同时写入完整资源文档、游戏源码和 BaseLib 源码。
6. 同步 README、工具说明和接口文档。
7. 执行知识库包相关定点测试与前端 typecheck。
