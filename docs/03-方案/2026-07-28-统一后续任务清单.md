### P0-2 错误暴露路径

目标：验证 LLM、图像生成、知识库、构建和打包失败时，GUI 能提供可行动的信息。

验收条件：

- [ ] 配置缺失、鉴权失败、网络失败和上游返回异常均有明确提示。
- [ ] 失败任务状态、history 与 audit 记录一致。
- [ ] 用户能够从提示中判断需要修改配置、重试还是检查外部环境。

### P0-3 真实工程构建

目标：使用真实 STS2/Godot 路径验证生成工程能够执行 `dotnet publish`。

验收条件：

- [ ] `local.props` 或本地路径覆盖正确生效。
- [ ] Harmony、STS2 和 Godot 依赖能够被项目解析。
- [ ] 构建输出可进入后续 package 流程。

2026-07-28 首次真实 `dotnet publish` 已执行：STS2 的 `SteamLibraryPath` 覆盖正确，但模板默认 `GodotPath` 在当前机器不存在，构建以 exit code 1 停止。下一步应先补齐真实 Godot/MegaDot 4.5.1 路径，再取得并处理生成 C# 的编译诊断。

### P0-4 安装版与 ML 首次运行

目标：分别验收 baseline 和 `-MlRembg` 安装版。

验收条件：

- [ ] 安装、启动、创建/打开工程和基本 job 操作通过。
- [ ] ML 版本首次 prewarm 能准备 ONNX Runtime，并能清楚暴露失败原因。
- [ ] 未启用或无法启用 ML 时，fallback 行为符合预期。

### P0-5 双进程工程锁

目标：手工验证两个独立桌面进程不能同时写入同一工程。

验收条件：

- [ ] 第一进程持锁时，第二进程得到稳定的工程占用提示。
- [ ] 第一进程正常或异常退出后，第二进程能够重新打开工程。
- [ ] 常驻 `.ats/lock` 文件不会造成假死锁。

### P0-6 发布候选验证

目标：在 P0-1 至 P0-5 阻断项清零后，形成桌面 MVP 发布候选基线。

建议验证：

- [ ] `cargo test --workspace`
- [ ] workspace 级 clippy

- [ ] 完整 Tauri baseline/ML 构建
