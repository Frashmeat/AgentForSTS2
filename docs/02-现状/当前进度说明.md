Pack v4 顶层 `itemTypes` 是 Mod 类型身份、canonical/localization fields、required locales、Evidence Queries、typed reference slots 和 conditional Resource profiles 的唯一真源；顶层 `compositionProfiles` 定义 preset/custom 参数、约束和 <=128 node 上限。`pack.mod-plan-guidance` v3 与 `pack.mod-generate-single` v4 contribution 版本暂不变化。

STS2 Pack 现正式注册 `custom_code`、`relic`、`card`、`potion`、`power` 和 `character` 六种类型。Character 声明 7 个 canonical fields、14 个 Character localization fields、6 个 typed reference slots、Placeholder/Branded Placeholder 两个 resource profiles 和 8 组 Truth Queries；Branded profile 精确要求五个静态身份 roles。`character_suite` 默认 Standard，也提供 11-node Prototype 与有界 Custom。`pack.composition-plan-guidance` v2 使用稳定 node groups、group dependencies、group-targeted binding/quantity rules 和 Suite Brief；Feature 据此编译 deterministic Blueprint。Standard 精确 35 nodes，Custom 在 Standard 上增加 8 个 Power 时为 43 nodes。当前 Pack v4 pinned SHA-256 为 `90b72f51911317e166802517329be5a5848b17b79961498953c5dfa72ee85df4`。

ItemDefinition v2 保存稳定 identity/type、canonical fields、Pack-keyed localization fields、behavior intent、Resource bindings、typed identity/pinned references 和可选 composition profile provenance。定义仍使用有序序列化计算 SHA-256；reference quantity 或 profile 参数变化都会产生新 hash。

Capability readiness 由 pinned Pack 与当前 verified Truth 确定性计算：未声明类型不出现；无当前 Truth 时所有已声明类型 blocked；部分 Evidence Query 不命中时只禁用受影响类型并返回 typed query-index blocker；ready 之前不得进入模型调用。

Item repository 使用 `.ats/items-v2/<itemId>/definitions/<definitionHash>.json` 保存新合同快照，并只原子更新 `current.json`。旧 `.ats/items-v1` 不迁移、不删除，历史候选仍只能证明旧代码。Tauri capability wire 新增 `compositionProfiles`，ItemDefinition enum payload 使用 camelCase。

CompositionDraft v2 使用 `.ats/composition-drafts-v2/<draftId>.json`，在原有 Pack/root/profile/nodes/revision 基础上增加 `sourceExecutionGraphId` 和 `validatedContentDigest`。普通审阅更新继续使用 revision CAS；Draft 新建和每次修订都会对内部 pinned DAG 自底向上重算 definition hash，因此 Resource、behavior 或 replacement 修改会在同一 revision 内传播到全部受影响祖先，同时保留 optimistic-current 基线和 staged provenance。分阶段提交使用 payload SHA-256 校验的 `createOrMatch`，只允许精确创建或幂等匹配，不覆盖冲突 Draft。旧 `.ats/composition-drafts-v1` 不迁移、不删除。

ExecutionGraphRecord v1 使用 `.ats/execution-graphs-v1/<executionGraphId>.json` 保存 owner/request/Blueprint identity、ordered nodes、logical attempts、hashed normalized checkpoints、active/previous Run、commit intent 和 final result ref。状态修改使用 revision CAS；Run 创建前必须先赢得 graph claim，Run create/start/persist 任一点失败都会尝试将 claim 补偿为 paused。Plan 使用 legacy-compatible Draft commit intent；Generate 使用互斥的 generic publication intent。两者都要求 `commit_prepared` 只前滚，不能回退到模型节点或混合两种 intent 形态。

ResolvedItemGraph v1 沿 pinned hash 展开精确 closure，identity affiliation 只在闭包内校验，不扩展版本。Resolver 在返回前验证 exact hash、Pack target type、Truth capability、definition Ready、Resource selection/version、cycle 和 128 node limit，并将排序后的 nodes/edges、Pack/Truth、可选 Draft revision、root/profile provenance 计算为稳定 SHA-256。Draft Shell 和 Composition Studio 已接入查看、编辑、删除与闭合子图原子确认；`composition.generate` 在 Run 创建前和 Feature 内重复解析完整 graph，再逐节点产生 Plan/Single child evidence。

O4 的生成发布路径不调用 Single 的即时工程写入或单项 Artifact。所有 proposed files 先进入 bounded `.ats/composition-staging/<runId>` 隔离副本，统一 validation 后执行带 `ModsPath` 白名单隔离输出的 Build 与 staged Package；源码和 ZIP 最后通过同一个 rollback-capable `ProjectFileWriter` transaction 写入真实工程，并只发布一个 composition Artifact。Single/Package result v2 以 `composition_staged` 区分内部 child 证据，Build request v2 只接收 normalized output root。最终工程 transaction 使用 `.ats/transactions/<runId>` 版本化 write records，并以同目录 `.committed-*` rename 作为 durable commit decision：prepared 恢复旧文件和本轮目录，committed 保留新文件并只清理 journal。`ProjectSession::open` 在 Run reconciliation 前执行恢复；损坏、重复或越界 record 会拒绝打开，不猜测成功。

ResourceAsset 使用 schema v2；`pack.resource-specs` 已升级为 v3，声明 exact media shape、direct master/derived graph 和可选 master-only `defaultAsset {id, sha256}`。Pack default 不接受调用方路径，而是按精确 Pack identity/asset ID 解析内嵌 bytes 并在 PNG 解码前复核 hash。STS2 的 512x512 `character.identity_master` 可确定性派生 85x85 顶栏 icon/outline、132x195 select/locked icon 和 49x64 map marker；512x512 `relic.master` 仍派生三个 Relic roles。Upload、AI 与 Pack default 都先产生 `selectedVersion=null` 的 immutable candidates；显式 select 后 Single 才接受精确版本。批失败回滚 staging/final 并保留既有 selected；派生 provenance 绑定 source role/version、transform Primitive/version/parameters hash 与 pinned Pack identity。Resource Workbench 按 catalog 的 `packDefaultAvailable` 通用显示 Default 操作，并继续按 Pack role 管理 preview、selected/bound 状态。

Single Generate request 为 v3。Batch request 已破坏性升级为 v4、result 为 v2：输入只包含 `modId`、固定 `StoredItemDefinition`/`definitionHash`、确定性 `artifactId` 和 `failFast`，Feature 为每项持久化 Plan child Run 后复用 Single v3；父 Run `succeeded` 表示编排完成，Item 失败保留在 typed result 中。Complex request 为 v3、result 为 v2，直接复用同一 Batch，只在全部 Item 成功后继续 Build/Package。公开请求不再接受 caller-authored Plan、`selectedResources` 或可编辑 JSON。Single 在创建 Run 和调用模型前验证 definition hash、Ready mode、Plan identity、required roles、selected pointer 与 Pack media shape；Prompt Recipe v3、ModelRequestSnapshot、Artifact extension v2 和 provenance 均绑定精确 `definitionHash`。

## 3. Prompt 与所有权

```text
Feature Recipe
+ Pack Contribution / selected Item descriptor
+ bounded Truth Evidence
+ Selected Resources
+ Project Context
+ llm.custom_prompt
+ Typed Output Contract
= ModelRequestSnapshot v1
```

跨游戏任务语言属于 Feature Recipe；游戏类型/字段/资源/查询和指导属于 Pack；当前 API 事实属于 Truth；资源版本属于 Workspace；用户补充指令属于运行时设置。代码只保留 role、schema、slot、JSON、安全、截断、脱敏、typed validation 和 Provider 调度等协议合同。桌面 composition root 持有唯一 `ModelRequestQueue`，一个逻辑任务连同全部重试占有一个 FIFO 席位直到终态；排队取消不发请求，队列状态不进入 Run 或 Artifact。

Plan result v2 的 `evidenceRequirements` 仍只描述业务证据意图。可执行 `symbols/terms` 查询来自 Pack v4 item descriptor；readiness 与 Single Generate 复用同一查询。Single 将所选类型的 `generatedFiles[].role` 编译为 run-scoped bundle v2 strict JSON Schema。
