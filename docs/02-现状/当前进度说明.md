当前 Composition Generate 的关键事实：

- 模型请求使用共享 FIFO 单飞队列；请求间隔、transport retry 与语义 feedback 分层处理。
- Direct Single 保持严格单次输出合同；Composition 可以对一个可唯一归因的 Item 执行 bounded semantic feedback。
- Graph-total repair policy 和 20 轮绝对上限防止无限循环。
- 本地环境、共享文件、归因不明确、重复诊断、未改变 candidate、取消和存储错误都会安全暂停。
- `commit_prepared` 只在 registered validation 成功后创建；发布仍是 whole-closure 原子事务。
- 当前限制：`repair_owner()` 要求全部 repairable issues 唯一属于同一个 Item，多个 owner 会得到 `validation.not_repairable`。

## 3. Pack、Item 与 Resource

STS2 Pack 精确注册六种 Item type：

```text
custom_code
relic
card
potion
power
character
```

```text
Pack SHA-256:
90b72f51911317e166802517329be5a5848b17b79961498953c5dfa72ee85df4

Character identity master SHA-256:
ec1b4f15aeb864166e0ec60936acfa390de9a0e9f2e06e41c5dc5a729a34c393
```

- Pack v4 是字段、localization、Evidence Query、typed reference slot、Resource profile 和 composition profile 的真源。
- Character 支持 Placeholder 和 Branded Placeholder。
- Branded Placeholder 由 512x512 master 确定性派生五个静态身份资源。
- Pack default 只按精确 Pack ID/SHA、asset ID 和 asset SHA 解析，不接受调用方路径。
- Upload、AI 和 Pack default 均先形成不可变 Resource candidate，只有显式 select 才改变 selected pointer。
- `character_suite` 支持 Prototype、默认 Standard 和有界 Custom；数量、依赖和引用均由 Pack 驱动。
