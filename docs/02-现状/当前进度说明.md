## 3. 生成与反馈闭环

- 所有桌面模型请求共享 FIFO 单飞队列；同一逻辑请求持有席位直到成功、耗尽或取消。
- OpenAI-compatible 使用 SSE；180 秒分别限制响应头和相邻 chunk 停滞，不限制活跃流总时长。
- `delta.content` 是主输出；整条流没有 content 时才使用完整 `reasoning_content`。
- Recipe 的输出值是业务上限；当前尚未实现用户配置的 Provider 输出上限，导致 Single 的
  `16,384` 预算会原样发送。已认可方案使用
  `min(recipe.maxOutputTokens, llm.max_output_tokens)` 在 snapshot 创建前解析有效预算。
- transport retry、typed output feedback 和 generated-content repair 是分层策略，不互相伪装。
- 多 Item generated-content issues 按 owner 和 DAG 顺序形成持久化、总预算有界的 repair campaign。
- shared、ambiguous、local、未改变 candidate、重复诊断和不可修复问题安全暂停。
- 单 Item 用户调整绑定 `itemId + expectedDefinitionHash`，只重生成目标 Item，随后完整复验。
- `commit_prepared` 只在 Provider-registered whole-closure validation 通过后创建；发布保持原子性。
- 不按模型名增加 JSON 猜测、Markdown 清理、字符串补丁、自动切换模型或并发轰击上游。
