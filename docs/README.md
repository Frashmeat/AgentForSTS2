> 文档定位：本文是 `docs/` 的唯一导航入口，负责区分稳定知识、当前事实、当前方案与历史材料。
>
> 事实依据：当前 `rust` 分支代码、Trellis 工作流和 2026-07-29 确认的文档治理原则。

> 最后更新：2026-08-06

## 核心原则

`docs/` 不管理具体任务。任务的 PRD、状态、执行记录、审查和验证过程统一由 `.trellis/` 管理；只有形成长期有效的项目知识时，才回写本知识库。

## 阅读顺序

1. 先读根目录 `PROJECT_SPEC.md`，确认协作规则和验证边界。
2. 需要理解系统时，读 [`01-总览/项目架构总览.md`](./01-总览/项目架构总览.md)。
3. 需要判断当前能力和缺口时，读 [`02-现状/当前进度说明.md`](./02-现状/当前进度说明.md)。
4. 需要理解当前方向和完成标准时，先读 [`03-当前方案/当前方案.md`](./03-当前方案/当前方案.md)，再按其中索引进入专题方案。
5. 只有追溯背景时才进入 [`90-归档/`](./90-归档/)。

## 维护规则

- 不为普通单个任务在 `docs/` 新建过程性计划、决策、审查或验证文档；经明确确认、仍指导当前实现的专题方案可保留在 `03-当前方案/`。
- 具体任务使用 `.trellis/tasks/<task>/prd.md`，完成后按 Trellis 工作流归档。
- 稳定架构变化更新 `01-总览/项目架构总览.md` 或资源总览；代码事实变化更新 `02-现状/当前进度说明.md`；阶段方向变化更新 `03-当前方案/当前方案.md`，专题细节更新对应专题方案。
- 被替代的文档移动到 `90-归档/`，不与当前入口并列。
- `docs/` 只保留本文件一个 `README.md`，子目录使用有明确主题的文件名。
- 修改目录或文件名时，同步更新 `PROJECT_SPEC.md`、本索引和仓库内引用。
